## 2. Proposed minimal schema (additive, no rewrites)

New file `src/semantic/visualStrategy.ts` (TS, same folder as atom/intent/contract; mirrored by `scripts/lib/` if scripts need plain-JS import):

```ts
export type StrategyName =
  | "DIRECT_SCENE"        // low risk, capabilities supported
  | "CONTRAST_ABSENCE"    // negation: show the claim's world WITHOUT the negated thing (insert/strike/absence)
  | "ABSTRACT_CONCRETE"   // metaphor: the concrete vehicle may appear only with its abstract tenor (labels/arc), never as a literal swap of the subject
  | "EXPLICIT_STATE"      // emotion inversion: state must be legible (expression + emotion overlay + arc), no neutral face on an inversion claim
  | "RELATION_LOCK"       // relation beats: cast>=2 with lookAt/position/interaction bound in contract evidence
  | "SAFE_REPRESENTATION" // low-confidence capability: keep the authored action, choose proven-safe framing/support (e.g. illustration/diorama hero + figure support), never swap the action
  | "UNRESOLVED";         // strategy cannot represent without changing meaning → plan stops (same semantics as P0.2 problems[])

export interface VisualStrategy {
  strategy: StrategyName;
  risks: string[];              // from failure-taxonomy classes + risk-selector features
  capabilityConfidence: number | null; // min over used capabilities (null = unmeasured)
  semanticSignature: {          // BEFORE/after equality check target (§ auto-repair)
    action: string; subject: string; relation: string; state: string; world: string; metaphor: string;
  };
  evidence: Record<string, unknown>; // strategy-specific requirements written INTO VisualContract.visualEvidence
}
```

Scene gets one additive field `_visualStrategy` (like `_authorship`), and `VisualContract.visualEvidence` gains strategy-required entries so the firewall enforces them. No new gate file: hard-gate gate 9 already consumes `problems[]`.

## 3. Risk → Strategy mapping (deterministic; inputs only from P1.1–P1.3)

| Risk signal (source) | Condition | Strategy |
|---|---|---|
| negation in caption (risk-selector feature; `visualIntent` contrast markers) | `\b(not\|never\|cannot\|can't\|without\|no longer\|stop)\b` in the atom text | CONTRAST_ABSENCE |
| metaphor (taxonomy METAPHOR OR `allegory_equivalence` intent with analogy markers) | atom text has figurative marker | ABSTRACT_CONCRETE |
| emotion-inversion (taxonomy STATE evidence pattern: "fails to convey", celebrate-on-lament) | STATE/EMOTION marker + mood somber | EXPLICIT_STATE |
| relation (cast ≥ 2 OR twoShot/overShoulder OR RELATION taxonomy) | multi-cast scene | RELATION_LOCK |
| LOW_CAPABILITY (visual-capability.json) | min confidence < 0.85 over the scene's used capabilities | SAFE_REPRESENTATION |
| UNKNOWN capability (unmeasured) | used capability missing from map | SAFE_REPRESENTATION (measure-first bias) — but if the authored action itself is the unmeasured/risky verb → UNRESOLVED unless a safe framing covers it |
| enum-invalid authored action (schema) | action ∉ charAction enum | UNRESOLVED (fail-closed; fixes the live push/gesture hole) |
| critical contradiction (firewall HC5/HC6 class) | existing hard constraint would reject | REJECT (unchanged; firewall stays last) |

Precedence (first match wins): enum-invalid → negation → metaphor → emotion-inversion → relation → low-capability/unknown → DIRECT_SCENE. Mapping lives in ONE table in `visualStrategy.ts`; audit (PHASE B) verifies each mapped representation against the actual renderer levers listed in §1.

## 4. Authored Action Lock (invariant mechanics)

- `sanitizeAction` (director-adapter): P1.4 replaces the silent `celebrate → think` with a recorded, authored-aware decision: heuristic beats keep the swap ONLY because `celebrate_action` is a contract trope (i.e., the *contract itself* forbids celebrate) — but it must then be logged as a strategy record with semanticSignature BEFORE/AFTER; authored beats (`_authorship.src !== "none"`) are never swapped (UNRESOLVED instead). This is the only place an action substitution exists today.
- Stagnation/novelty engines (auto-repair path): PHASE E adds the semantic-delta audit (below); PHASE B–D do not touch them.
- Test list (authorship): for `fall→? collapse→? fight→? push→? grab→? cry→? angry→? cannot-lie→? metaphor→?` — strategy may add framing/support/text/props but `characters[].action`, atom.subject/action/relationship, contract.semanticCore must be byte-identical before/after. `test-authorship-gate.js` extended with a `stagingDrift`-style assertion on `_visualStrategy` application.

## 5. Auto-repair semantic-risk audit design (PHASE E)

New `scripts/audit-auto-repair-semantics.js` + lib function `semanticSignature(config)` (sha over per-scene `{action[], expression[], subject(visualProposition.subject), relation(narrativeRelation), state(narrativeState), worldId, metaphor(intent archetype + icon concept), text[]}`):

1. Run `autoRepairAntidote` on a corpus (the 3 measured books + any unpublished config).
2. Diff signatures per scene per repair type → report `{repairType, scenesTouched, semanticDelta: {action: nChanged, …}}`.
3. Wire a **SEMANTIC_REVIEW_REQUIRED** rule into auto-repair: any mutation that changes signature fields on an AUTHORED beat → the repair is rejected (config returned without it) and the event recorded; on heuristic beats the delta is allowed but recorded in `repairs[]` (no silent path anymore).
4. Deliverable: `data/auto-repair-semantic-audit.json` + the report printed. **No tuning of retention logic in this phase.**

## 7. Fresh blind holdout protocol (PHASE G — the gate that proves 10×)

1. **Unseen corpus:** 20–30 fresh scenes sampled from NEWLY planned (not-yet-rendered) unpublished books, stratified to oversample low-confidence/unmeasured capabilities: fall, collapse, fight, push, grab, struggle, reach, overShoulder, surprised, crowd, cast:3 (exact sampler = risk-selector with `--mode=holdout`, excluding any frame previously judged).
2. Plan each scene twice: **A = current pipeline** (strategy off), **B = strategy on** (same authored beats untouched — verified by signature diff).
3. Render both to PNG (same frames budget as mute test).
4. Blind vision mute test (file-based rater, same protocol as P0.1; rater model recorded; vision is a validation instrument only).
5. Metrics: per-frame majority GOOD/WRONG/UNCERTAIN; **primary = Gate PASS → Vision WRONG rate, A vs B**; secondary = risk-selector Top-K recall ON HOLDOUT (never fed back into the map); capability map stays frozen from PHASE C.
6. Decision rule agreed in advance: B adopted only if B's WRONG rate < A's with no authored-action violations and no gate regressions; otherwise strategy features stay diagnostic and we go to P2 rig work instead.
