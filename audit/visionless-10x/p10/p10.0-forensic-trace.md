## 6. Minimal implementation proposal (Phase 1–2 için, operatör onayına)

1. **Concrete Visual Scene Plan = beat brief extension (yeni truth source DEĞİL).**
   `books/<slug>/beat-briefs.json` mevcut `proposition` + `antidote` bloğunun yanına
   `visual` bloğu: `{subjects, setting, action, objects, relation, perPole:[{evidence,
   forbidden}], representable}`. Yalnız author brief'lerinde; detection bunu uydurmaz.
2. **UNREPRESENTABLE birinci sınıf sonuç.** Plan aşamasında per-pole representability
   değerlendirilir; çizilemeyen kanıt için yapısal down-grade YOK, `UNREPRESENTABLE`
   raporu + (opsiyonel) `customSvg` per-book asset önerisi.
3. **Renderer primitifleri — 4 genişletme, beat-hack değil:**
   a. **sequence** prop: 2 adımlı nedensel olay (storm→flood) tek ikon çifti,
      cause_effect auth'lu beat'lerde kullanılabilir (029).
   b. **cast bible expansion** (ITW antidote world): isimli karakterler + jest yönü
      (accept/reject jestleri = lookAt + action çifti kuralı) (155).
   c. **physical-state profil**: cast variant zaten beard/build/height destekliyor —
      brief `visual.subjects[i].state` → variant eşlemesi + otobüs set adayı (174).
   d. **competing-hypothesis composition**: split'in yerine iki SOMUT motif + "??"
      epistemic marker (belirsizlik korunur) (266).
4. **Verifier**: mevcut firewall/proposition gate'lerin YANINA Layer-A kontrolü
   (visual blok ↔ scene config alan eşleşmesi, deterministik); Layer-B (piksel) yalnız
   kör değerlendirme + contact sheet, PASS sayacı policy'e GİRMEZ.
5. **Ölçüm**: policy dokunulmaz (WRONG/DEAD blocking, ADDS hedef); yeni veri yalnız
   raporlama (P10.4 kalite snapshot).

Risk: (a) `sequence`/`customSvg` genişletmesi firewall'da yeni yüzey alanı → provenance
testleriyle sarmalanır; (b) ITW cast bible'ı uydurma-karakter riski → yalnız kitapta
adı geçen kişiler; (c) emülsiyon: 4 fixture başarısı genel çözüm sanılmamalı — P10.4
