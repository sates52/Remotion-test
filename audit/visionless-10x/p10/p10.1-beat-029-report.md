## 5. UNREPRESENTABLE / capability ledger (the honest boundary)

Rendered within the frozen schema with ZERO renderer code changes:

5.1 **Water color** — the `water` motif paints ink+accent waves; with no scene
accent it renders as dark ink on dark ground (first pixel check caught this:
blueBias −21). Fixed with the engine's legitimate per-scene accent lever
(`transition.color` = ITW water blue) and a full-bleed water placement
(scale 3.4 puts the icon box's side edges past the safe frame — the flood reads
as a full-width churning channel, not a rectangular slab). No code changed; the
levers were always there.

5.2 **Represented** — storm cell with animated rain + flickering bolt (the
engine's own storm icon); flood water surging in the channel (the engine's own
water icon); the cause→effect descent as a composed left-to-right stroke (arrow);
ITW palette/world; muted frame (no copy, no captions, no cast — by authoring).

5.3 **UNREPRESENTABLE in the current engine** (proof, not complaint):
1. **No desert/arroyo set.** The 26-set enum has no desert, wash or arroyo;
   `horizon` is a generic landform; `mountainSlope` exists but only via a book's
   own world declaration (Camus) and is a slope, not a channel. The wash is
   carried by gradient + palette + icon composition — the *place itself* is not
   drawn.
2. **No water transformation.** The storm icon rains in place; the water icon
   surges in place; **no primitive joins rain→runoff→flood inside one object**.
   `stateIndex` exists per-prop but nothing chains two props into one causal
   state machine. The descent is spatial (composition), not physical (motion).
3. **No per-pole icon binding in the frozen contract.** `poleIconOwners` accepts
   a single `visual.icon` with strict verbatim equality — a two-pole frame
   without copy can anchor only through `compositionCoversBoth`
   (split/beforeAfter/twoShot). Pictorial per-pole evidence is invisible to the
   gate. (The pixel check fills that hole objectively, but the *contract* cannot.)
4. **customSvg is static.** The per-book `customSvg` door draws static paths with
   a single draw-in ramp — no frame-driven animation, no multi-state flood, no
   travelling token outside the flow diagram (whose token is a dot between
   LABELLED CIRCLES — the exact "two circles" failure).

## 6. Recommendation (for the operator's decision — nothing mandated)

The minimal, generalizable next step (post-P10.1, not implemented here):
1. **Per-pole icons in the seal** — extend `visual.icon` → `visual.perPoleIcons[]`
   (verbatim text→icon map, same strictness). Small, backwards-compatible, and it
   makes the frozen contract *see* pictorial anchors. This alone upgrades #029's
   evidence class from composition-bound to per-pole icon.
2. **A desert/arroyo set** in the book's own world declaration (same pattern as
   `mountainSlope` for Camus) — ITW declares `washArroyo` once, Backdrop gains
   one parallax set. Optional; the composition already reads without it.
3. A true **rain→runoff→flood state machine** is the only genuinely missing
   renderer capability; the least-complex version is a single `washFlood`
   motif with 3 states driven by `stateIndex` (dry → filling → surging), one
   file, no schema change.
