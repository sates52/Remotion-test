# P10.2 — Integration Design: authored visual brief → production Director

**STATUS: DESIGN ONLY. No production file touched. STOP honored (operator directive, 2026-10-07).**

Fixes the two P10.1 findings the operator confirmed: (1) the #029 scene was hand-authored
in `p10.1-fixture.json` — storm/water motifs, coordinates, scales and the arrow were
operator-written; (2) `twoSided=true` was only composition-bound — `stagedPoles()` accepts
a `beforeAfter` shot as pole evidence without any per-pole pictorial proof on the pixels.

The real threshold (operator): **on a NEW book, without anyone writing coordinates by hand,
the Director stages the right visual.** Not more tests passing — authored decisions reaching
production pixels.

---

## 1. Current production flow (what exists today)

```
beat-briefs.json  (authored briefs, src:"claude", per beat:
                    narrative_intent / visual_intent / narration span)
      │
      ▼
scripts/plan-antidote.js            [1334 lines]
  intentOf(brief) → drawSceneForLexArg (CONCEPT_LEXICON) → buildScene
      │
      ▼
scripts/lib/proposition.js  stageProposition(seal, scene)
  — P9-B stager: shot from representation, flow diagram, perCast, concept icon
      │
      ▼
scripts/lib/authorship.js  authorshipStamp → config.antidote.json
      │
      ▼
Remotion (src/engines/antidote/*) — Scene.tsx / motifs.tsx draw it
```

The gap: between the brief's prose and `stageProposition`'s levers there is only the
lexicon. A brief that says *"storm over the wash, then the flood fills the channel"* has
no route into scene props except a human writing the fixture by hand (exactly what P10.1
did). And `stagedPoles` cannot see pictorial evidence per pole — its only composition
evidence is the ALWAYS_TWO_SIDED shot shortcut.

## 2. Target data flow (the design)

One new file + minimal edits, everything through existing levers:

```
beat-briefs.json
  briefs[i].visual = {                                    ← the AUTHORED visual plan
    subjects:  ["storm", "floodwater"],        // enum names ONLY (motif library)
    setting:   "desert wash, horizon low",     // free text, prov bound to narration
    action:    "rain falls, water rises into the channel",
    objects:   ["cloud", "rain", "water"],
    relation:  "cause_effect",                 // mirrors proposition.relation
    perPole: [                                 // per-pole pictorial ownership (NEW)
      { pole: "storm hits the wash",     icon: "storm"  },
      { pole: "flash flood fills it",    icon: "water"  }
    ],
    forbidden: ["cast", "captions", "city"]    // author's must-not-show list
  }
        │
        ▼
scripts/lib/visual-compiler.js          ★ NEW — the only new logic in the system
  compile(brief.visual, bookWorld, propLibrary) →
  {
    ok: true,
    scene: { props: [ {type, role:"pole-0"|"pole-1"|"relator"|"setting",
                       band:"sky"|"ground"|"channel", scale:"m"|"l"|"xl" } ],
             composition: "cause_effect"|"before_after"|null },
    unrepresentable: [ { requested:"arroyo wash",
                         reason:"no set/motif for desert channel in the 26-set enum",
                         suggestion:"washArroyo set | add set" } ],
    dropped: []                              // everything authored either lands or is named
  }
  HARD RULES (compiler contract):
    R1  It never invents an icon name: every prop type must exist in
        src/engines/antidote/motifs.tsx MOTIFS (the same closed enum the renderer
        draws). A name not in the enum → unrepresentable[], never a generic fallback.
    R2  It never writes pixel coordinates. It writes BANDS + SIZES (semantic slots);
        a single layout function (bandToXY) maps band→x/y deterministically.
        Coordinates remain the renderer's own geometry, authored once, in ONE place.
    R3  It never silently drops: any authored subject that cannot be drawn is
        returned in unrepresentable[] with reason + suggestion (P10.1 ledger style).
    R4  Forbidden list is enforced: forbidden subjects can never be compiled into
        props; a conflict is an error, not a filter.
        │
        ▼
plan-antidote.js                        ✎ EDIT (~40 LOC, one hook point)
  after buildScene, before stageProposition:
    const vc = visualCompiler.compile(brief.visual, world, lib);
    scene.props.push(...vc.scene.props)      // bands → xy via the ONE layout fn
    scene._authorship.visualCompiled = vc    // stamp for the gate + audit
        │
        ▼
scripts/lib/proposition.js              ✎ EDIT (evidence path only)
  + perPoleIcon: seal.visual.perPole[] (NEW, optional) — per-pole icon ownership,
    strict equality on pole text/entity (same rule as today's poleIconOwners, but
    plural). stagedPoles: a pole with perPole icon on scene → "staged-pictorial".
    twoSided stays the same VERDICT — but for beats with perPole evidence it can
    now be earned pictorially, not only via the composition shortcut.
  + UNREPRESENTABLE surface: if _authorship.visualCompiled.unrepresentable.length
    and the beat would otherwise PASS → the gate reports VISUAL_UNREPRESENTABLE
    (REPORT severity first, HARD behind a flag when the operator flips it).
        │
        ▼
Remotion                                ★ UNTOUCHED — motifs.tsx already draws
                                          every prop the compiler can emit.
```

Why a compiler and not "ask the LLM for x/y": the operator's own P10.1 lesson — the
fixture's hand coordinates were fine once, but they are not a *system*. Bands+sizes are
authored decisions; pixels are renderer geometry. One layout function = every scene from
every book gets the same sane composition rules (safe-area, occlusion, sky/ground
grammar) for free, and P10.1's "arrow pointing into empty space" class of bug becomes
impossible by construction.

## 4. Design requirements → how each is met

1. **beat-briefs.json authored visual evidence read by plan-antidote** — the `visual`
   block on each brief; plan-antidote's one hook consumes it. Briefs without `visual`
   behave exactly as today (§5).
2. **Author decisions bound to visual-strategy / Director / Remotion schema** — the
   compiler's only output vocabulary is the motif enum the Remotion schema already
   accepts; relation mirrors `proposition.relation`; perPole mirrors the seal.
3. **Drawable evidence → real scene objects** — props land via bandToXY with
   `role` tags so the arrow/relator is placed *between* pole bands by geometry,
   not by hand.
4. **Undrawable → UNREPRESENTABLE, never generic wallpaper** — R1/R3; `idleWallpaperOf`
   already detects the failure shape, and the new gate code makes it loud.
5. **composition-bound ≠ semantic PASS** — pictorial per-pole evidence becomes a first-
   class verdict (`staged-pictorial`); reports distinguish `twoSided(composition)` from
   `twoSided(pictorial)`. Only the latter counts toward the operator's semantic bar.
6. **Not storm/water-specific** — the compiler knows NOTHING about storms; it maps
   `{enum name → band + size}` for all 26+ motifs and all relations. New book, new
   causal event: as long as the author picks enum names, the same path runs.
7. **Frozen books / other agents / quality policy** — see §5.

## 5. Backward-compatibility risks (and mitigations)

| Risk | Mitigation |
|---|---|
| Old briefs lack `visual` → compile must not fire | Hook is `if (brief.visual)` — null path is today's exact behavior, byte-identical configs |
| A compiled prop changes an existing scene's authorship stamp | New stamp field `visualCompiled` only; existing `conceptAuthored`/`propositionAuthored` untouched |
| New verdicts change gate PASS/FAIL for current books | `VISUAL_UNREPRESENTABLE` ships REPORT severity first; HARD flip is a one-line policy change the operator owns |
| `stagedPoles` verdict changes break 342 frozen tests | Pictorial evidence is ADDITIVE (new verdict value on beats that have perPole); composition shortcut untouched — regression suite must stay green unchanged, proven before merge |
| plan-vox parity | Same hook shape added to plan-vox.js in a second step (or explicitly deferred with the operator's OK) |
| Render bundles judge config-only | perPole lives in the seal (`sealFor`), so gates inside render bundles need no brief file — same property the current contract has |

## 6. Test scenarios (write before implementation)

1. **Unit — compiler purity:** every prop type out of `compile()` ∈ motif enum; zero
   absolute coordinates anywhere in output; bands/sizes only.
2. **Unit — unrepresentable:** `visual.subjects:["arroyo"]` → `unrepresentable[{reason,
   suggestion}]`, no prop, no fallback motif, scene otherwise unchanged.
3. **Unit — forbidden:** `forbidden:["cast"]` + compiler asked for a character prop →
   hard error (not filtered).
4. **Integration — the real threshold beat:** take a NEW book's beat-briefs.json (not
   ITW), author the `visual` block for one cause_effect beat, run plan-antidote end-to-end,
   render the PNG. Human (operator) judges semantic truth. **This is the P10 gate.**
5. **Regression:** full frozen suite (342 tests) unchanged-green; the P10.1 25-test
   fixture contract still passes with perPole added to its seal.
6. **Gate:** a config with `unrepresentable[]` non-empty + `VISUAL_UNREPRESENTABLE`
   REPORT → gate PASSes but reports; flipped to HARD → fails. Both directions tested.
7. **twoSided honesty:** a beforeAfter scene with perPole icons present →
   `twoSided(pictorial)=true`; same scene without the icons → `twoSided(composition)=true,
   pictorial=false` (distinction visible in report JSON).

## 7. What this does NOT do (honest ledger)

- It does not make the LLM author choose icons autonomously from prose — the authored
  `visual` block is still human/agent-authored per beat. Automating *that* (brief →
  visual block) is a later phase and should be judged on its own output.
- It does not add new motifs or sets (washArroyo, multi-state flood) — those are the
  P10.1 §6 suggestions, operator's call.
- It does not touch Vox pipeline in the first cut (parity step optional).
